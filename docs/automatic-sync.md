# 打开 App 后自动同步

iOS 与 Android 共用根布局中的 `AutoSync`、登录入口、本地模式开关和全局同步任务。

- 设备未开启本地模式且已有登录会话时，冷启动、登录成功、从后台回到前台会静默执行一次同步。
- 系统短暂进入 inactive 状态（如打开通知中心）和同一用户的令牌刷新不重复触发同步。
- iOS 冷启动的原生状态可能为 inactive 或尚未读取到状态（null），此时等首次 active 再开始；返回前台时的 background → inactive → active 只触发一次。
- 自动与手动入口均调用 `runManualSync`，由进程内唯一的 `syncTask` 共享进行中的 Promise。去重覆盖读取本地模式、检查会话、上传、下载、合并、同步设置和写回元数据的整个流程。
- 自动同步不显示弹窗。进行中点击同步按钮，显示该任务当前进度并订阅后续进度，不创建第二条管道；完成后更新首页数据和主题。
- 自动同步失败时不弹出打断操作的对话框，首页显示云端离线图标。点击可重试，下次回到前台也会重试。
- 设置中的“本地模式”默认关闭，按设备持久保存，不上传到账号设置。开启后自动与手动同步均不访问云端。正在同步时需等待完成后切换；关闭本地模式后，已登录会话会触发同步。
- 同步期间发生的本地新增、编辑、删除和设置修改保留待同步状态，供下一次同步上传，避免被同步开始时的旧快照覆盖。退出登录等待当前管道结束后再清空本地账号数据。

这里的后台同步指 App 内静默执行；App 关闭后不运行系统后台定时任务，也不对每次编辑即时上传。

## 验证

`npm run test:auto-sync` 覆盖共享任务身份、进度接入、失败重试、登录及前后台生命周期、本地模式零网络请求、真实同步入口与仓库写回的隔离测试。云端通过替身模拟，未使用真实账号上传或改动生产数据。

另运行 TypeScript、lint、现有本地同步、进度与项目结构检查。双端正式发布状态见 [1.0.11 发布记录](releases/1.0.11.md)。

iOS 补测覆盖 inactive/null 冷启动、通知中心、后台返回、原生 AppState 与登录事件接线、手动任务复用及监听清理。测试使用事件替身，不等同于 iPhone 真机验收。
